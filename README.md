# 🌍 WARE-Net: West Africa Road Extraction Network

This repository contains the official PyTorch implementation of **WARE-Net**. It is a pioneering visual foundation model-based dual-stream architecture designed for fine-grained road surface classification in highly complex remote sensing environments.

> **📊 Data Availability:**
> The first high-resolution road surface cartographic product generated by WARE-Net, covering 286 cities across 15 West African countries, is publicly available on Figshare: [**https://doi.org/10.6084/m9.figshare.31725265**](https://doi.org/10.6084/m9.figshare.31725265).

---
## Overall Workflow
**WARE-Net** is a deep learning-based framework designed for road extraction from high-resolution satellite imagery in West Africa. This framework leverages a dual-stream decoupled architecture based on a visual foundation model, aimed at extracting both paved and unpaved roads with high accuracy. The model has been trained on the **WARE dataset**, the first manually annotated dataset tailored to the unique multi-modal characteristics of West African road networks.

The WARE-Net framework operates in the following four major stages:

### 1. **Data Preparation**
The first step involves collecting high-resolution satellite imagery and key socio-economic covariates, including HDI, population density, nighttime light intensity, and built-up area. These data are used for subsequent road surface classification and socio-economic analysis. The **WARE dataset** is constructed by sampling regions based on geographical and climatic heterogeneity and manually annotating paved and unpaved roads.

### 2. **Model Design**
In this stage, WARE-Net is trained using a dual-stream decoupled architecture built upon the **DINOv3** visual foundation model. The model is designed to extract both **local texture information** (using the LTIE module) and **global topology features** (via the MGTIE module) to effectively address challenges like material confusion and topological fragmentation. The model’s predictions are further refined during inference using **test-time augmentation (TTA)** and the **hysteresis topology repair (HTR)** strategy.

### 3. **Accuracy Assessment and Product Generation**
Once trained, WARE-Net is used to generate high-resolution road-surface maps covering 286 cities across 15 West African countries. The results are validated by comparing with existing road products like **OSM** and **Liu et al. (2026)**. The generated road-surface product is evaluated for completeness, spatial accuracy, and material classification reliability.

### 4. **Road Pattern and Drivers Analysis**
Finally, the generated road-surface product is used to calculate **city-level paved road rates**, which are then analyzed for spatial heterogeneity using **Geographically Weighted Regression (GWR)**. This analysis reveals the relationship between road development and socio-economic drivers such as population density, HDI, and economic activities. The insights gained are used to inform infrastructure planning and policy development, supporting the **Sustainable Development Goals (SDGs)**.


## 🌟 Key Features

* **Foundation Model Encoder:** Leverages the deep semantic priors of a pre-trained DINOv3 (SAT-493M) backbone for robust feature extraction across diverse topographies. 
* **Dual-Stream Decoupled Decoder:**
  * **Local Texture Decoder:** Employs multi-scale dilated convolutions (DBlock) for fine-grained material perception, effectively distinguishing dirt roads from bare soil. 
  * **Global Topology Decoder:** Integrates a Mamba-based Selective State Space Model with a 2D cross-scan mechanism (SS2D) for long-range structural reasoning, overcoming severe canopy occlusions. 
* **Robust Inference & Post-processing:** Includes our novel Hysteresis Topology Repair (HTR) algorithm and Test-Time Augmentation (TTA) to ensure engineering-grade structural integrity.

## 🚀 Getting Started

### 1. Environment Requirements
Our codebase is built upon PyTorch. To ensure absolute compatibility with the visual foundation model encoder, you must first configure the environment according to the official DINOv3 setup.

* Refer to the [**Official DINOv3 Repository**](https://github.com/facebookresearch/dinov3) to install the core dependencies and download the pre-trained weights (`SAT-493M`). 
* The `dinov3` folder should be placed under this root directory. Alternatively, you can edit the path directly in your execution script.

### 2. Installing Mamba Architecture
After setting up the base environment, you need to install the dependencies for the Global Topology Decoder (Mamba SS2D). Due to specific CUDA requirements for the Selective State Space Model, please carefully install the following packages:

```bash
pip install causal-conv1d
pip install mamba-ssm
```
*(Note: Ensure your CUDA version matches the requirements of `mamba-ssm` to successfully compile the custom kernels.)*

### 3. Configuration
Before running the code, update the local paths to point to your downloaded dataset and pre-trained weights.
1. Open `run.sh` in the root directory.
2. Modify the `DATA_DIR` and `WEB_PTH` variables to match your local environment setup.

### 4. Training and Inference

> **⚠️ Hardware Notice:** All experiments and the default training scripts in this repository were originally conducted on a Linux Ubuntu 22.04 high-performance computing cluster equipped with **8× NVIDIA A100 Tensor Core GPUs (80 GB memory per node)**.

**Multi-GPU Training (Default):** The provided scripts are optimized for Distributed Data Parallel (DDP) across 8 GPUs. To run the training in the background (preventing the process from terminating if your SSH connection drops), use:
```bash
nohup bash run.sh > output.log 2>&1 &
```


**Single-GPU Training:** If you intend to run the training on a single GPU, you must modify the code to bypass the DDP initialization and adjust the batch size accordingly to prevent Out-Of-Memory (OOM) errors.
